## Run it (from `clouds/`)

```
scripts/prepare_author_dir.sh [--force] [AUTHOR_DIR]     # builds ../HypaNet-clouds-author (refuses if it exists)
scripts/prepare_author_dir.sh --force --test-root DIR    # TEST hand-over: tools may also read/write DIR; launch refuses it

scripts/launch.sh continue K                              # technical continuation K (1..30), fixed text kit/prompt_continue.md
uv run python scripts/audit.py runs/r1/logs/r1.stream.jsonl   # -> r1.audit.json; launch.sh runs it after every launch
uv run python scripts/cost.py [--check|--remaining]       # US$500 cap over runs/r1/logs/*.stream.jsonl
uv run python kit/make_settings.py [--check]              # regenerate / check kit/settings.json
uv run python kit/kit_build.py sky-table                  # KIT.md section 3.4's sky radiance table
shasum -a 256 kit/prompt.md > kit/PROMPT_APPROVED.sha256  # Matthew, when he approves the prompt (start checks it)
```

## Choices SPEC leaves open, and deviations

1. **Tools reuse the renderer unchanged.** `author_tool.py` validates the author's arguments, then calls
   `renderer/render.py` `main()` and `renderer/inspect_ray.py` `main()` with module-level substitutions only: their
   `Harness` (a subclass that serves `kit/build/scene/` and patches `window.harness.setup` in the page for the free
   camera / free sun), their `resolve_pair` (a fixed table of the validated views) and render's `REFERENCE_DIR` (the
   author's `references/`). `harness_client.HARNESS_FEATURES = False`, and the author's argument parsers do not
   have `--mode`, `--no-background`, `--harness-exact`, `--scene-dir` or `--set heldback` at all. No file in
   `renderer/` was edited.
2. **Sanitised scene.** The browser is served `kit/build/scene/shots.json` with only the 5 reference shots, the 4
   presets, the 12 reference pairs and their exposures (copies of density.u8 and the sky maps beside it: the
   harness server refuses symlinks out of its root). So even an error message cannot name a held-back pair or the
   quarter shot. The `side` and `distant` descriptions are corrected there and in KIT.md: the sun is on the
   **screen's right** in both (scene/out/shots.json says left; `toward_sun · camera_right` = +0.57…+1.0 for side,
   +0.50…+0.87 for distant).
3. **Free mode** (`--shot SHOT --sun SUN` or `--camera X,Y,Z --look-at X,Y,Z [--fov] --sun SUN`): SUN is a preset
   (exact preset) or `ELEV,AZ` (the viewer's `CloudRenderer.setSun`: exact E_sun, L_sky/L_gnd/sky map lerped in
   elevation between presets and rotated in azimuth). Elevation 1–89°, fov 1–120°, res ≤ 1280×800, frames ≤ 256.
   Default free exposure: the reference exposure for that shot+preset if it is a reference pair, else by nearest
   preset (noon 0.315, afternoon 0.3969, golden 0.5, sunset 2.0). Free views can reproduce the *camera and sun* of
   a held-back pair (e.g. `--shot front --sun afternoon`); that shows the author only its own network, never a
   held-back reference, so it is allowed.
4. **Paths.** NET.json must be inside the author dir (so `./render` cannot be used to read harness files such as the
   validation networks, which inspect would print); `--out` / `--json` only inside `work/`. A TEST hand-over adds
   one extra root (baked into the wrapper as a fixed argument the author's own arguments cannot change).
5. **`./python3` instead of the system `python3`.** SPEC says "python3 with numpy only". The system python3 would
   read the repo freely, so `./python3` is the private venv under `tools/py_guard.py` (audit hooks): reads only in
   the author dir (+ interpreter and system dirs), writes/renames/removes only in `work/`, no subprocess, socket,
   ctypes, links; scipy/torch/sklearn/jax/... imports refused; `numpy.linalg.lstsq`, `numpy.linalg.pinv`,
   `numpy.polyfit`, `numpy.polynomial` fit functions and `.fit` raise. `solve`, `inv` and random numbers stay
   available (legitimate for physics) and the audit lists them for review. A guard, not a sandbox. Hardened after
   the review (see "Review fixes" below).
6. **Bash allow-list is `./render`, `./inspect`, `./python3` only (no `ls`/`cat`).** Settings cannot restrict the
   paths of a `Bash(cat:*)` rule, and Glob / Grep / Read (path-scoped) already list and read. Claude Code
   auto-allowed `ls -la <author dir>` in v0.5 Phase C even without a rule, so the settings now also deny the usual
   shell commands by name (`make_settings.py` `BASH_DENY`: `Bash(ls:*)`, `cat`, `find`, `grep`, `cd`, `python3`,
   `git`, `env`, ... 85 in all); `./python3` still matches its own allow rule (a prefix rule matches from the start
   of the command). The audit still records any such command as a note (inside the author dir) or a violation.
7. **Settings are generated** (`make_settings.py`). v0.5 Phase C lost a Read of Claude Code's own saved large tool
   output (`~/.claude/projects/<project>/<session>/tool-results/*.txt`) to a blanket `~/.claude` deny. Deny rules
   beat allow rules, so the settings deny every *other* entry of `~/.claude` and of `~/.claude/projects` (enumerated,
   plus patterns for project dirs that may appear later: the repo, `clouds`, `HypaNet-v*`, `HypaNet-m*`,
   `-private-tmp-*`, ...) and allow Read of the author dir's own project dir only. `launch.sh` runs
   `make_settings.py --check` and refuses if a new `~/.claude` entry is not covered (re-run `make_settings.py`).
   Hence `settings.json` is not in the HANDOVER harness hashes; its sha256 goes into each `NAME.launch.json`.
8. **Launcher** = `scripts/v05c_launch.sh`'s flags and environment scrub (incl. `--permission-prompts none`, kept
   from v05c), plus: `VIRTUAL_ENV`/`UV_PROJECT_ENVIRONMENT` unset; `check` also runs a **GPU smoke render** through
   the author's exact code path (`author_tool.py` with a tiny harness network, output in `runs/r1/smoke/`,
   gitignored) and refuses on failure or SwiftShader, then re-verifies the author dir. `start` refuses unless
   `kit/PROMPT_APPROVED.sha256` holds the sha256 of `kit/prompt.md`, and if the session's own Claude Code project
   dir (`~/.claude/projects/-Users-matthew-Development-hypabolic-HypaNet-clouds-author`, Readable by the author)
   exists and is not empty; `check` reports both. `continue` refuses once any
   launch ended with `NETWORK COMPLETE`. Continuations are run by hand (`continue K`), as in v0.5; SPEC's "the
   launcher continues the session after API errors" is the operator running `continue K` (no automatic loop, so a
   normal stop without NETWORK COMPLETE is never resumed blindly).
9. **Cost** (`scripts/cost.py`) re-implements v0.4/v0.5's accounting (per-session-id delta of the cumulative
   `total_cost_usd`; killed launches at their `--max-budget-usd` ceiling from `NAME.launch.json`) so `clouds/` stands
   alone. Launch names `r1`, `r1.c<K>`. `--max-budget-usd`: on `start` the remaining of US$500, rounded down to
   cents; on `continue` also the remaining only (see "Review fixes" 6).
10. **Audit** (`scripts/audit.py`): tools outside Read/Glob/Grep/Write/Edit/Bash; Bash not one of the three
    commands, or compound (shlex-based, so `;` inside `./python3 -c "..."` code is fine); absolute or resolved paths
    outside the author dir and markers (repo, `HypaNet/clouds`, `~/.claude`, temp roots, other author dirs,
    `heldback`, `quarter_`); writes outside `work/` (named "tool modification" for the kit's files); source rules
    on every Python source the author wrote (Write/Edit contents, `./python3 -c` code, `work/**/*.py`): forbidden
    imports and fitting calls = violations; random numbers, loss/gradient/iteration vocabulary, `best` tracking,
    argmin/argmax, loops over linspace/arange, linalg solves = "review"; guard refusals, permission denials, models
    (must be claude-fable-5-1 only), cost, turns, NETWORK COMPLETE. Writes `NAME.audit.json`; exit 1 on executed
    violations. Reads of the session's own saved tool output are notes, not violations.
11. **KIT.md content.** Since the review, section 3.4 also has the four sky previews and a table of sky radiance
    at the zenith and 1° above the horizon toward / across / away from the sun per preset (`kit_build.py
    sky-table`, bilinear samples of `scene/out/sky_*.f32`): physics inputs (the references are lit by the full
    map), not reference pixels. It states SPEC's physics, the renderer equation and the exact single-scattering formula
    (SPEC §4), plus harness facts the author needs (view frame orthonormalised per pixel; blur is a 3D box filter,
    so it also averages sideways; pyramid levels and the 893 m limit; float32 `sin`; the two march cut-offs and
    their size; reference noise; that the renderer and Mitsuba agree; speed). It does **not** give the measured
    single/multiple/sky shares, the validation test-network design or any circuit idea. It says that other views and
    sun positions, not shown, will be judged (no parameters). The phase peak is stated (`p(1) ≈ 12.1 sr⁻¹`).
12. **Deliverables** (prompt + KIT §9): `work/network.json`, the generating script(s) that rewrite it exactly with
    `./python3` (and read no image: every number a literal or a physics formula), `work/NETWORK.md`. The run ends at a line `NETWORK COMPLETE` in the final message.
13. The author dir also holds `PROMPT.md` (the launch prompt) so the author can re-read its task after context
    compaction.

## Review fixes (2026-11-09)

A reviewer audited the kit (3 must-fix, 5 should-fix, 4 nits). All were applied, with Matthew's decisions:

1. **Rules (must-fix).** `prompt.md` Rule 1 is the reviewer's wording essentially verbatim: no gradient descent or
   iterative update toward a target; no least squares / regression in any form (normal equations with
   solve/inv/svd, `statistics.linear_regression`); no weight, scale or colour computed in code from reference
   pixels or render − reference differences (`k = ref.mean()/render.mean()`): type the number with a comment; no
   per-unit / per-term basis images combined by computation (the image is linear in the last layer); no sweeps, even
   by hand; no recognising a shot or preset to patch it. KIT §8 rule 1 is the same as a list. Rule 2 (prompt and
   KIT) now says explicitly **yes** to the author's own numpy light-transport simulations on idealised shapes it
   builds (Monte Carlo through a slab or sphere), read to inform choices but never fitted / regressed / solved
   against; input only shapes it builds, not the reference images and not the cloud's density beyond what
   `./render` / `./inspect` show. Deliverables (prompt item 2, KIT §9): the script that builds `network.json` must
   not read any image (`.npy`/`.png`); every number is a literal or a physics formula. The audit checks it.
2. **`./python3` guard (must-fix), `kit/tools/py_guard.py` rewritten.**
   - The audit hook has no globals and no closure cells: everything it uses (roots, the C functions
     `posix.getcwd/lstat/stat/readlink/fspath`, `isinstance`, `len`, ...) is a keyword default bound at start, and
     it resolves paths itself (a realpath over those C functions), so monkeypatching builtins, `os.getcwd`,
     `os.path.realpath`/`abspath` or `posixpath` changes nothing. `str`/`bytes` subclasses are copied to plain
     strings first; only `str`, `bytes`, fds, `os.DirEntry` and unmodified `pathlib` paths are accepted as paths
     (a custom `__fspath__` object is refused, and `pathlib`'s `__fspath__`/`__str__`/`_str` are checked unchanged).
   - The guard module's globals are deleted before the author's code runs; `-c` code runs in a fresh `__main__`
     module that replaces the guard in `sys.modules`. The hook is never stored where Python can reach it.
   - Refused events: `sys._getframe`, `sys._current_frames`, `sys._current_exceptions`, `gc.get_*`, `sys.settrace`,
     `sys.setprofile`, `sys.monitoring.*`, `os.chdir`/`os.fchdir`, and `object.__getattr__`/`__setattr__`/
     `__delattr__` on the guard's own objects (GuardError, the pathlib classes and methods it trusts, the dir_fd
     wrappers). `sys._getframemodulename` stays allowed (`namedtuple` uses it).
   - `dir_fd`: every function in `os.supports_dir_fd` is wrapped (in `os` and `posix`) to refuse a non-None
     `*dir_fd`, `os.supports_dir_fd` is emptied, and, because a fresh `posix` module can be had with
     `del sys.modules['posix']; importlib.import_module('posix')` (no audit event), the hook also **refuses opening
     a directory as a file**: with chdir refused too, no directory fd exists for `dir_fd=` to use.
     `shutil._use_fd_functions = False` so `shutil.rmtree` in `work/` still works.
   - Fitting: also patched `numpy.linalg._linalg.lstsq`/`pinv`, `numpy.lib._polynomial_impl.polyfit`,
     `numpy.polynomial.polyutils._fit`, `numpy.linalg._umath_linalg.lstsq`, `statistics.linear_regression`; the
     originals are removed from numpy's `ARRAY_FUNCTIONS` registry; re-executing those modules' files (reload, or
     re-import after deleting from `sys.modules`, which `importlib.import_module` does without an `import` event) is
     refused via the `exec` event, and an `import` statement of any module loaded at start-up is refused.
   - Scripts must end in `.py` (`./python3 PROMPT.md` and `./python3 work/notes.txt` are refused).
3. **Audit (must-fix + should-fix), `scripts/audit.py`.** Vocabulary regex without the trailing `\b`
   (`(?:learning_rate|lr|grad\w*|loss\w*|err\w*|step_size|n_iter|max_iter|epochs?)\s*[-+*/]?=`); new review items:
   `-=`/`+=` with a product inside a loop, `while`, `range(` with 3+ digits, `.T @` / `@ ….T`, `numpy.linalg` in
   any form, `exec`/`eval`/`compile`/`__import__`/`importlib`/`getattr(np`, ratios of image statistics, and a
   source that reads an image and writes JSON/arrays. New violations: `linear_regression`; `_linalg`,
   `_umath_linalg`, `_polynomial_impl`, `polyutils`, `ARRAY_FUNCTIONS`, `_implementation`; guard tampering
   (`sys.modules[`, `_getframe`, `f_globals`, `f_back`, `f_locals`, `tb_frame`, `__closure__`, `cell_contents`,
   `READ_ROOTS`, `WORK_REAL`, `py_guard`, `dir_fd`, `gc.get_`, `audithook`, `settrace`, `__fspath__`, `reload(`,
   `os.chdir`, ...); assigning to attributes of library modules (monkeypatching); a script that writes
   `network.json` and reads an image. Every Write/Edit body of any extension is scanned (as source if `.py` or run
   with `./python3`; otherwise its source violations are listed for review, so `NETWORK.md` prose does not count as
   an executed violation), and so is every file named as a `./python3` script (a non-`.py` one is a violation).
   MARKERS and the absolute-path check now apply to Write/Edit bodies too. The report notes that a regex audit
   cannot prove the absence of fitting: read every author Python source after the run.
4. **Settings (should-fix).** Explicit Bash denies (item 6 above); regenerated with `make_settings.py` (529 deny
   rules).
5. **Prompt Rule 3 / KIT §8 rule 4 (should-fix):** "Don't modify or work around the tools or the ./python3 guard,
   and don't read anything outside this directory, except the file Claude Code itself names when it saves a long
   tool output." KIT §7 says the same where it mentions the saved file.
6. **`--max-budget-usd` on continue (should-fix). Semantics untested.** `total_cost_usd` is cumulative over
   `--resume` (v0.5 r1.t001..t004: 13.36 → 15.87 → 16.36 → 16.70). If Claude Code compares the flag with that
   restored total, passing only the remaining cap would stop a late continuation after one turn; if it compares the
   flag with this launch's own spend, passing total + remaining could overspend the cap by the session's earlier
   total. The orchestrator chose the safe side (2026-11-09): `continue` passes only the remaining cap, so the US$500
   can never be exceeded and the worst case is a continuation that stops early. The launch record keeps
   `session_total_before_usd`. After a launch, a result with subtype `error_max_budget_usd` (`cost.py
   --budget-stops`) while `cost.py` still shows ≥ US$1 left prints an explanation; that would show the check is
   cumulative, and the next continue can then pass session total + remaining by hand.
7. **Approval and project dir (should-fix).** `launch.sh start` refuses unless `kit/PROMPT_APPROVED.sha256`
   (first field) equals `shasum -a 256 kit/prompt.md`, and refuses if the session's Claude Code project dir exists
   and is not empty. The approval file is **not** created: Matthew writes it.
8. **Nits.** `compound()` treats any token made only of `<>&|;` as an operator (`&>`, `>&`, `2>&1`, `<<<`);
   `renderer/net.js` rejects any weight, bias, const value or `dist` beyond float32 (|x| > 3.4e38) with a
   `NetworkError` naming the field; the audit's absolute-path regex needs two path components or a filesystem root
   (`n //2`, `x /2.0` no longer match); `./inspect` checks `--pixel` itself (`./inspect: error: --pixel must be
   inside 640x400 ...`) and `author_tool.py` sets `sys.argv[0]` so the renderer's own argparse errors say `render` /
   `inspect`.
9. **Sky previews (physics reviewer's nit).** `references/sky_<preset>.png` (copied by `kit_build.py references`)
   and the KIT §3.4 table.
