# slop/codex/lists/ui_instruction_markers.txt
# Words and frames that open an instruction: a sentence telling the reader what to do next. Patterns: U14
# (instruction sentence, KEEP), U15 (instruction that only restates a visible control, ECHO/NARRATE), U19 (error body
# with a remedy), U35 (empty state with next action), and the decision aid in CODEX.md §7.
#
# Use: an instruction is KEEP evidence (Microsoft's "main instruction" is the top-ranked copy in a window; LABELLING.md
# K8 keeps an empty or error body that gives the next action) unless the rest of the sentence only (a) names a visible
# control by its own label ("Save your changes." beside "Save changes"), (b) names a gesture on a visible control
# ("Click the button below"), or (c) names ordinary platform behaviour ("Scroll to see more"). Those three are the
# restating cases; see ui_narration_verbs.txt for the gesture and layout words that mark (b) and (c).
#
# Format: one entry per line, lower case, natural spelling; fold the same way as the rule layer (rules/README.md,
# "Normalised string"). Match imperative leads at the start of a sentence; match frames anywhere. Lines starting with
# # are comments.
#
# Provenance: written for HypaNet. Verb choice follows the Microsoft Writing Style Guide, "Describing interactions with
# the UI" (input-neutral verbs: open, close, go to, select, choose, clear, switch, turn on, turn off, enter, move, drag,
# zoom; learn.microsoft.com/en-us/style-guide/procedures-instructions/describing-interactions-with-ui), Apple HIG
# Writing ("be clear about what someone can do to fix it") and NN/g error-message guidelines ("offer some potential
# remedies"). Licence: MIT (repo licence).
