# slop/codex/lists/llm_narration.txt
# Lexical cues for NARRATE copy: text that explains how the visible interface works, what a visible control does, or
# what the reader can already see. Patterns: L36 (captions narrating controls), L37 (layout and
# self-description). LABELLING.md §3 NARRATE, §7 consequence test; [anti-slop-guides] R6 and R16.
#
# These are cues, not verdicts. A cue makes a node a NARRATE *candidate*; the consequence test (LABELLING.md §7) still
# decides: "Hold Shift to select a range." names a hidden input and is KEEP (K4), "Tap a card to open it." is NARRATE.
# Entries in section "hidden-input cues" point the other way (towards KEEP) and are listed so a rule or a network
# concept can tell them apart.
#
# Format: one phrase per line (alphabetical within each block), lower case, natural spelling; fold before matching. {x} = one to eight words, as in
# llm_constructions.txt. Lines starting with # are comments.
# Provenance: patterns written for HypaNet from GOV.UK ("If you find yourself having to explain how the user
# interface works..."), Microsoft UI text ("don't explain the obvious"), unslop-ui TELLS.md §8 "Over-explained
# microcopy/tooltips", tasteskill copy.md "Explainer captions that narrate the design", humanizer §25 "writing about
# the document", stop-slop "Meta-commentary" (all cited in [anti-slop-guides] and SOURCES.md).
# Licence: MIT (the HypaNet repo licence).
